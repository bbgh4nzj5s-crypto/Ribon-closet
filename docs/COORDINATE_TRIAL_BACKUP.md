# 試作コーデ専用バックアップ・復元（未公開）

基点215ca878df02076e71a8524abc382929faa6f4e2。ブランチprototype/coordinate-trial-backup。既存の正式DBや通常バックアップの形式は変更しない。

## 操作
試作コーデ一覧の「試作データのバックアップ・復元」から利用する。
1. 編集中の場合は先に「保存」または「あとで続きを登録する」を実行する。未保存の入力は含めない。
2. 「バックアップを保存」でJSONを作成する。ブラウザーのダウンロード先を確認する。
3. 「バックアップを選択」で検証。コーデ・パーツ・画像の件数、同じIDの件数、参照先がない既存アイテムの件数を表示する。この段階では保存しない。
4. 同じIDがある場合は「同じIDの試作データを更新する」をチェックし、さらに確認して復元する。同意しなければ既存レコードは更新しない。
5. ファイルにないコーデ・パーツは削除しない。通常のMyクローゼット・Pro・通常下書きには書き込まない。

## 内容と安全性
専用DB ribbon-coordinate-trial の coordinates / parts を同一読み取りトランザクションで取得。フル画像、個別画像、原QR写真、再生成QR、読み取り失敗写真をBlobの実バイトで保持。共通画像は内容とMIMEが同じ場合に重複排除。リンクID・設定・下書き状態も保持する。正式itemsの本体や画像は収録しない。別端末では正式アイテムを別途復元する必要があり、参照が不明でもIDは保持して警告する。

復元前に専用形式/version、ID重複、カテゴリー、リンク、タグ、所持/ほしい/お気に入り、画像参照と容量を検証。QRはデジタル画像と原写真を再復号し、両方が保存済みのバイト列と一致することを確認する。復号できない、または不一致なら復元しない（既存データを保持）。読み取り失敗写真は未検証写真のまま復元する。1件でも検証に失敗したら書き込みを始めない。

復元は専用DB内の単一トランザクション。同じIDの存在をトランザクション内でも再確認し、同意のない更新を防ぐ。途中のput失敗は全体をロールバック。試作DB名以外は受け付けない。外部送信・公式サイトアクセス・有料APIなし。

試作として画像実容量256MiB、入力JSON384MiB相当までの検証上限を設ける。超過時は中止して元の記録を維持し、切り捨てや画質変更はしない。この上限までiPhoneで動作する保証ではない。JSON/Base64のため元画像よりファイルと作業メモリが増える。大きな写真、Safariのメモリ上限、実機ダウンロード/ファイル選択は未検証。
